03 · Apply and test

Perform — Step by Step

Complete in order, checking each result before moving forward. Read the Extra Help if something does not work.

Tool and resource

Open TurboWarp. Work in your existing project. No new account, extension or download required.

  1. Open your working Turkey Escape project at https://turbowarp.org/. Verify the player still responds to arrow keys. Click 'Choose a Sprite' in the Sprite pane and select a simple obstacle such as a ball or rock-like image; rename the new sprite Obstacle if useful.
    Extra Help: Check that you selected the correct sprite and block category. Compare your values and block order with the instruction above. If the output differs, fix this step and retest before proceeding.
  2. Select ONLY the obstacle sprite in the lower-right pane. In Events, bring 'when green flag clicked' into the Code workspace. Attach Control → 'forever'.
    Extra Help: Check that you selected the correct sprite and block category. Compare your values and block order with the instruction above. If the output differs, fix this step and retest before proceeding.
  3. Inside forever place Motion → 'go to x: [0] y: [170]'. Replace the 0 with Operators → 'pick random [-200] to [200]'. Each cycle should start the obstacle in a possible new horizontal position.
    Extra Help: Check that you selected the correct sprite and block category. Compare your values and block order with the instruction above. If the output differs, fix this step and retest before proceeding.
  4. Beneath the go-to block, still inside forever, add Control → 'repeat until < >'. Build the condition with Operators → less-than and Motion → y position reporter: '(y position) < -170'.
    Extra Help: Check that you selected the correct sprite and block category. Compare your values and block order with the instruction above. If the output differs, fix this step and retest before proceeding.
  5. INSIDE repeat until, connect Motion → 'change y by [-5]' followed by Control → 'wait [0.05] seconds'. A negative change moves down. Keep these blocks inside the repeat, not outside.
    Extra Help: Check that you selected the correct sprite and block category. Compare your values and block order with the instruction above. If the output differs, fix this step and retest before proceeding.
  6. Click green flag. Watch the obstacle fall below the stage and restart at the top; it should repeat without clicking anything. Watch at least three full falls and notice whether x changes.
    Extra Help: Check that you selected the correct sprite and block category. Compare your values and block order with the instruction above. If the output differs, fix this step and retest before proceeding.
  7. If it only falls once, check that the entire go-to and repeat-until sequence is inside forever. If it moves upward, change y by -5, not +5. If it never resets, check whether the condition compares y position to -170.
    Extra Help: Check that you selected the correct sprite and block category. Compare your values and block order with the instruction above. If the output differs, fix this step and retest before proceeding.
  8. With the game still running, use the arrow keys. Verify that the player and obstacle are separate sprites and both scripts respond. Do NOT add collision, scores or lives today; those belong to the later build.
    Extra Help: Check that you selected the correct sprite and block category. Compare your values and block order with the instruction above. If the output differs, fix this step and retest before proceeding.
  9. Save with the approved method. Write a three-line explanation: what stays the same when this loop is reused for a following enemy, what movement rule would change, and how to test the adapted version.
    Extra Help: Check that you selected the correct sprite and block category. Compare your values and block order with the instruction above. If the output differs, fix this step and retest before proceeding.
