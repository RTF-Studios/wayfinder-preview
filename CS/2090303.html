01 · 4 minutes

Connect: Think Like a Player

Two people pass the same obstacle. The game gives one of them five points and the other one point. Is that fair? How should the score be decided?

Think / tell a partner: Answer in one sentence. No prior coding required.

02 · 8 minutes

Vocabulary and the Big Idea

A player needs trustworthy feedback. A score variable must change exactly once per successfully passed obstacle. A condition can raise the obstacle speed only at clear milestones.

  • Variable: a named value the game remembers and updates.
  • Condition: a yes-or-no rule used to choose an action.
  • Score: the number of completed successful passes.
  • Progression: a planned change in challenge as players succeed.
03 · 25 minutes · local editor

Make It Work

Continue yesterday’s saved TurkeyEscape.sb3. Check that score, speed, and playing are global variables; passed belongs to the Pipes sprite.

  1. Open TurkeyEscape and click green flag. Confirm Space moves Turkey and Pipes travels from right to left. Fix these essentials before adding score.
  2. Select Pipes. Keep its existing movement script. Inside the existing forever loop, after moving the pipe left, add the score-on-pass check shown below. Do not make a second pipe movement loop.
  3. After a pipe crosses Turkey’s fixed x position (-120), add one point only if passed was 0; then make passed equal 1.
  4. When the pipe wraps to x=260, reset passed to 0 so the new pass can score once. This reset should already exist from Tuesday.
  5. Inside the same Pipes loop, choose speed based on score: 4 at first, 5 at five points, 6 at ten points. Place this before the movement block.
  6. Show the built-in score variable monitor on the stage; label Space and restart instructions. Test one pass, no duplicate points, next pass, and at least one speed change. Save.

Add to Pipes’ existing forever loop — one copy of each check

if <(score) >= (10)> then
  set [speed] to (6)
else
  if <(score) >= (5)> then
    set [speed] to (5)
  else
    set [speed] to (4)
  end
end

[existing block: move the pipe left by speed]

if <<(x position) < (-120)> and <(passed) = (0)>> then
  change [score] by (1)
  set [passed] to (1)
end

[existing wrap check: when x < -260, go to x 260 and set passed to 0]

Test trick: To verify level 2 without playing for a long time, temporarily set score to 5 while the green flag script is running; observe the faster pipe, then restart with green flag to return to zero.

Done today: score increases exactly once per completed pipe pass, speed rises at a milestone, and visible score matches events.
