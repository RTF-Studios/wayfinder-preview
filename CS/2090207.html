volunteer.html — safe demonstration reference
<!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width,initial-scale=1">
<title>Volunteer/Events — The Giving Table</title>
<link rel="stylesheet" href="styles.css">
</head>
<body>
<header><h1>The Giving Table — Volunteer/Events</h1>
<nav aria-label="Main navigation">
  <a href="index.html">Home</a>
  <a href="about.html">About/Contact</a>
  <a href="donate.html">Donate Food</a>
  <a href="volunteer.html">Volunteer/Events</a>
  <a href="recipes.html">Recipes</a>
</nav>
</header>
<main>
<h2>Neighborhood Meal-Packing Day (fictional)</h2>
<p>Saturday 10:00 a.m.–noon. No actual location or registration.</p>
<p class="notice">Classroom demonstration only. No real volunteer registration takes place. Do not enter real personal information.</p>
<section aria-label="Non-submitting demonstration">
<label for="sampleName">Example name — use invented text only</label>
<input id="sampleName" type="text" placeholder="Sample Student">
<label for="sampleEmail">Example email — use example@example.test only</label>
<input id="sampleEmail" type="email" placeholder="example@example.test">
<button type="button">Demo only — nothing is sent</button>
</section>
</main>
<footer>Fictional classroom website. No real donations, contact or registrations.</footer>
</body>
</html>

  1. Create volunteer.html with the shared semantic page structure, header and navigation.
    Create volunteer.html alongside the other pages. The same five navigation paths must be present.
  2. Add the fictional event details and a prominent message: 'Classroom demonstration only. No real volunteer registration takes place. Do not enter real personal information.'
    Put the disclaimer before the controls; clearly state that the event has no actual location or registration.
  3. Build visible labels linked by matching for/id attributes to sampleName and sampleEmail controls; use harmless example placeholders only.
    Match sampleName to its label for and sampleEmail to its label for. Use placeholders from the supplied reference, never real names/emails.
  4. Use a type=button non-submitting demonstration control, no action endpoint, no JavaScript network request and no data storage.
    Use the supplied section of controls with type=button; do not wrap it in a submitting form or add scripts, storage or an action address.
  5. Use Tab to check keyboard movement and compare the form at wide and narrow browser widths. Confirm clicking the demo button does not navigate or transmit data.
    Press Tab to each link and control; verify a visible focus indicator. Click the demo button with invented sample text: the page should stay put and nothing should be sent.

Event and disclaimers are obvious, labeled controls are usable via keyboard, and no submission/storage/network behavior exists.
